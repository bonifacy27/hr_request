# Текстовый PDF оффера для согласования

Установить `offer_secure_cli.php` и `offer_secure_pdf.php` рядом с существующим
`offer_cli.php`. Генератор использует то же расположение ядра Bitrix
(по наличию `bitrix/modules/main/include/prolog_before.php` в родительских
каталогах), инфоблок 218 и `/tcpdf/tcpdf.php` в корне портала.
Например, для `/home/bitrix/www/forms/staff_recruitment/offer/` корень
автоматически определяется как `/home/bitrix/www`, независимо от текущей
рабочей папки при запуске CLI.

```sh
php offer_secure_cli.php 3513128 3513128_approval.pdf
```

Результат: `/upload/application/offers/secure_pdf/3513128_approval.pdf`
относительно корня портала. На каждом запуске создаётся новый случайный пароль из 8 символов: латинские
буквы A–Z/a–z и цифры 0–9 (обязательно есть буква и цифра). Пароль
сохраняется в `PDF_PASSWORD` (ID 3197, одиночная строка инфоблока 218). Шифрование: AES-256
(TCPDF `SetProtection`, режим 3). Требуются PHP OpenSSL, поддержка AES-256 в
установленном TCPDF и шрифты `dejavusans`/`dejavusansb` из комплекта TCPDF.
PDF имеет формат A4, чёрный текст, выделенные подписи полей и автоматические
переносы страниц. Фоновые изображения и Montserrat не требуются.

После формирования PDF утилита записывает его через файловый API Bitrix
в свойство оффера `OFFER_PDF_DRAFT` (ID 3196, инфоблок 218, тип «Файл»,
одиночное). При повторном запуске значение заменяется новым PDF.
Файл и пароль записываются одним вызовом `SetPropertyValuesEx`.
Проверяются настройки обоих свойств и результат записи: новый ID файла,
исходное имя, размер и совпадение записанного пароля. Успешное завершение выводит ID прикреплённого файла;
при ошибке записи утилита завершается с кодом 1. Созданный PDF остаётся
в `secure_pdf`, даже если прикрепление не удалось. Файл в свойстве хранится
в стандартном файловом хранилище Bitrix и также зашифрован сгенерированным паролем.

Поля и условия вывода взяты из `offer_cli.php`: кандидат, телефон и дата отправки,
должность, подразделение, руководитель и его должность, фиксированная зарплата,
премия (месячная/квартальная), ИСН, РК, средний доход и оговорка об НДФЛ,
испытательный срок, дата выхода, тип договора, политики компании, офис/формат,
график/начало дня, оборудование, срок действия предложения и контакты рекрутера.
Юридическое лицо также выводится текстом. Сохраняются проект «Телемагазин» и
исходные условия вывода ссылки на сайт. Телефон и дата отправки в текстовом
документе выводятся и для Телемагазина. Пустые значения обозначаются прочерком.
Статический текст из фоновых JPG не переносится: он отсутствует в исходном PHP.

Это отдельная CLI-утилита, использующая административный контекст существующего
генератора. Web-вызов закрыт. Каталог создаётся с правами 0700, файл — 0600.
Вызывать генерацию и читать вложение должен тот же системный пользователь.
PDF сразу шифруется; незашифрованный промежуточный файл не создаётся.
Имя результата принимает только латинские буквы, цифры, `_`, `-` и `.` с
расширением `.pdf`. Финансовые значения и пароль не журналируются.

Генерация пароля использует `random_int`; пароль не выводится в CLI или лог.
Повторный запуск заменяет и файл, и пароль. Отправка письма и обработка ответа
здесь не реализованы.

## Проверка

```sh
php tests/offer_secure_pdf_test.php
TCPDF_TEST_PATH=/path/to/tcpdf/tcpdf.php OFFER_TEST_PDF=/tmp/offer_demo.pdf php tests/offer_secure_pdf_test.php
```

Вторая команда создаёт PDF с демонстрационными данными и документ с длинным
значением для проверки переноса страниц. Проверены реальные PDF на TCPDF 6.7.8:
AES-256, открытие с `test`, отказ с пустым/неверным паролем, кириллица,
экранирование HTML и перенос длинного текста на несколько страниц.
Bitrix и реальные данные оффера в окружении разработки отсутствуют;
запуск по реальному ID нужно проверить на портале.
